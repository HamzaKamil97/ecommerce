Behaviour contract (what the implementation will do):
• On register mount → syncCatalog(vendor_id) populates Dexie db.catalog (offline-first; cached snapshot shows instantly on reopen, refresh in background).
• Grid renders from db.catalog — not the hardcoded QUICK_TILES. Manager-added products appear automatically.
• Search filters by name / sku / barcode (client-side over the cached catalog). Department chips filter by merch_category_id (newly added to the snapshot). Chips are built from the categories actually present.
• Favorites = locally pinned tiles (stored in Dexie config), the "quick tiles" affordance for fast access. Starts empty; tap ★ / long-press to pin. (Tab kept; pin interaction can be a fast-follow if you'd rather ship All-items + search first.)
• Tile shows emoji/image, name, correct price (price bug fixed), and live stock. Out-of-stock dimmed; low-stock amber.
• Tile tap → existing useCart.addLineFromScan({variant_id,name,unit_price_minor,qty:1}) + beep. Cart math untouched.
• Empty state when catalog has 0 items; "no match" state when a search returns nothing; skeleton while first sync runs.
• Scanner keeps working too (now that Dexie is actually populated, findByBarcode resolves real items).
